# Тестирование панели управления Telegram-ботом

## 📋 Краткое описание

Практическое тестирование реального проекта — веб-панели `panel.kabanya.ru` 
для управления Telegram-ботом модерации чатов и каналов.

| Поле | Значение |
|------|----------|
| **Роль** | QA Engineer (практика) |
| **Длительность** | Сентябрь–Октябрь 2026 |
| **Тип тестирования** | Функциональное, права доступа, UI, API |
| **Найдено багов** | 3 (Critical, Major, Minor) |

---

## 🎯 Что тестировал

- Права доступа (Administrator, Moderator, Developer)
- Фильтры модерации (упоминания ботов, стоп-слова, анти-инвайт)
- Страницы: «Главное», «Пользователи», «Чат», «Администрирование»
- API-запросы через DevTools
- Уведомления и счётчики непрочитанных

## 🐞 Найденные баги

### Баг №1: 403 Forbidden при загрузке административных данных

| Поле | Значение |
|------|----------|
| **Severity** | Critical |
| **Priority** | ASAP |
| **Статус** | ✅ Исправлен, верифицирован |

**Описание:**  
При открытии страницы «Главное» и вкладки «Пользователи» под ролью Administrator 
запросы `/api/admin/users` и `/api/admin/permissions` возвращали 403 Forbidden.

**Что сделал:**  
- Обнаружил 403 через DevTools (Network, Console)
- Оформил баг-репорт со скриншотами
- После фикса проверил, что запросы возвращают 200 OK
- Оставил комментарий о верификации

📄 [Полный баг-репорт](./bug-reports/bug-403-forbidden.md)

---

### Баг №2: Фильтр упоминаний ботов пропускает слитные упоминания

| Поле | Значение |
|------|----------|
| **Severity** | Major |
| **Priority** | High |
| **Статус** | ✅ Исправлен, верифицирован |

**Описание:**  
Фильтр «Удалять упоминания сторонних ботов» корректно удалял `@bot test123`, 
но пропускал `@bottest123` и `start@bot123` (слитное написание).

**Что сделал:**  
- Проверил разные варианты написания упоминаний
- Зафиксировал закономерность (с пробелом — удаляется, слитно — нет)
- Оформил баг-репорт с примерами
- После фикса проверил все позитивные и негативные сценарии

📄 [Полный баг-репорт](./bug-reports/bug-bot-mentions.md)

---

### Баг №3: Уведомление «Упоминание в чате» возвращается после прочтения

| Поле | Значение |
|------|----------|
| **Severity** | Minor |
| **Priority** | Normal |
| **Статус** | ✅ Исправлен, верифицирован |

**Описание:**  
После прочтения сообщения с упоминанием уведомление «Упоминание в чате» 
появлялось повторно при обновлении страницы, переходе между разделами 
и в новой сессии браузера. Счётчик непрочитанных не сбрасывался.

**Что сделал:**  
- Воспроизвёл баг: прочитал сообщение → обновил страницу → уведомление вернулось
- Оформил баг-репорт со скриншотами и шагами
- После фикса проверил все сценарии: F5, переходы, новая сессия
- Подтвердил, что уведомление больше не возвращается

📄 [Полный баг-репорт](./bug-reports/bug-mention-notification.md)
